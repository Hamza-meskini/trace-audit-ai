# TraceAudit AI — end-to-end review, 8 November 2026

Scope: backend (FastAPI, SQLite and Databricks SQL), audit pipeline (ingestion, extraction,
retrieval, verification, aggregation), frontend (TanStack Start), deployment config, tests
and the saved benchmark history. The fixes are on branch `review/hardening-2026-11-08`
(5 commits on `main`, 34 files, +1,080/−146 lines). Nothing has been pushed.

Evidence tags:

- **CERTAIN**: reproduced by a test or probe, or read directly in the code.
- **LIKELY**: strong code evidence, not reproduced.
- **VERIFY**: needs a real Databricks workspace or a benchmark run to confirm.

## Summary

The architecture is sound and better than most LLM audit tools:

- Python, not the model, aggregates verdicts over an explicit logic tree.
- The review gate only adds reasons and never rewrites a verdict.
- An LLM failure degrades to "needs review", never to SUPPORTED.
- All SQL is parameterised.
- The UI copy is honest.

Four kinds of problem stand between it and a platform an auditor can trust:

1. **Operational bugs that broke the deployed product.** Review saves fail on Databricks,
   commits are lost after a 200 response, SQLite locks for the whole audit, and the event
   loop freezes for about 7 s per requirement. All of these are fixed on this branch.
2. **Auto-closure trust.** A PROVEN result can auto-close on numbers the LLM supplied that
   are never checked against the quote. A one-word quote such as "PASS" can bind to any
   evidence item. Not fixed: the fix changes verdicts and needs benchmark runs.
3. **Data egress.** By default, customer document text goes to third-party free model routes
   (TokenRouter GLM, Gemini embeddings, an OpenRouter vision fallback) even with
   `LLM_PROVIDER=databricks`. Not fixed: this is a product decision.
4. **The accuracy ceiling is CONFLICT handling.** Across 5 saved Nova runs, accuracy is a
   mean of 88.33% (range 85.42–91.67%). Three CONFLICT requirements are missed in all five
   runs, for causes traced to specific lines below.

## What's good

- **Verdict engine design.**
  - Exact-offset span validation and full-quote provenance repair.
  - Four-axis tri-state evidence qualification keeps "unknown" separate from "mismatch".
  - Pint unit conversion returns UNRESOLVED instead of guessing.
  - A secondary adjudicator runs on a different model.
- **No injection classes found.**
  - Every Databricks SQL statement uses `?` parameters.
  - Table, volume and endpoint names are regex-validated.
  - The frontend renders document and LLM text as plain text; no `dangerouslySetInnerHTML`
    is in use.
  - CSV formula guards exist on both ends.
- **Ingestion.**
  - Layout-aware chunking keeps tables with their headers repeated.
  - Bounding-box provenance is preserved, and decorative images are filtered.
  - The Docling crash on Windows/Python 3.13 is guarded.
- **Databricks client.**
  - Honours Retry-After with a cap and jitter, and bounds attempts.
  - Remembers JSON-schema capability and rejects truncated output.
  - Sends a request id for correlation.
- **Observability defaults.** MLflow traces record content hashes, not content, unless you opt in.
- **Benchmark discipline.**
  - Frozen evaluator-only answers, with ground-truth hashes stored in each run.
  - Offline re-scoring.
  - Per-run artifacts that include contracts and raw LLM condition results.
- **Tests and types.**
  - 442 backend tests at the start of the review; strict TypeScript (`noUncheckedIndexedAccess`,
    `exactOptionalPropertyTypes`).
  - Route-level code splitting.

## Open issues, ranked

### Critical

**C1. A PROVEN result can auto-close on unchecked LLM facts. CERTAIN** (code and probe).

- **The observed value is never checked against the quote.**
  `verification_reasoner.py:_structured_numeric_status` compares the LLM's
  `observed_value` to the threshold, but never to the cited text.
  - Probe: the quote says "6.2 ms", the LLM reports 4.2, the requirement is ≤5 → auto-closed SUPPORTED.
- **Only FAILED gets the consistency check.** FAILED must be EXECUTED + OBSERVED + VIOLATES
  (`verification_reasoner.py:1022-1031`). PROVEN has no equivalent check.
  - Probe: a planned, unexecuted step cited as PROVEN → auto-closed.
- **The secondary adjudicator never re-checks these.** It runs only on "Needs review"
  items (`pipeline.py:903-918`).
- **Fix:**
  - Require the normalised observed value to appear inside the exact cited span.
  - Require EXECUTED + OBSERVED + SATISFIES for PROVEN; otherwise set UNRESOLVED.
- **Benchmark caveat.** The README's "0 unsafe auto-closes" holds on the benchmark set
  only; it does not cover these cases.

**C2. Citation grounding accepts one-word quotes and silently re-points them. CERTAIN** (code and probe).

- **The mechanism.** `_attach_literal_citation_spans` (`verification_reasoner.py:605-637`):
  - has no minimum quote length;
  - after the cited items, searches *every* evidence item;
  - overwrites `evidence_ids` without a note.
- **The consequence.** A bare "PASS" from another requirement's row can ground a PROVEN.
- **Fix:**
  - Require a minimum of 4 tokens.
  - Search only the items the model cited.
  - Require full containment for PROVEN and FAILED.
  - Flag one span reused for different conditions.

**C3. Customer documents go to third parties by default. CERTAIN** (config and routing code).

- **TokenRouter (free route).** `ATOMIC_DECOMPOSITION_MODEL="z-ai/glm-5.3-free"`
  (`config.py:121`) is forced to TokenRouter by `resolve_llm_provider` (`llm_client.py`),
  even with `LLM_PROVIDER=databricks`. Every requirement's source block goes to a free
  third-party route.
- **Gemini embeddings.** They are used whenever a Gemini key exists and AI Search is off,
  which is the default. Evidence chunks and requirement text go to Google. Your local cache
  already holds 1,689 such vectors.
- **Vision fallback.** If Databricks vision fails, page images and up to 6,000 characters of
  spec text cascade to OpenRouter's free route, then Gemini, Groq and Hugging Face.
- **Fix:**
  - Add one data-egress allow-list that defaults to Databricks-only, with
    `databricks-gte-large-en` for embeddings.
  - Record the provider and served model per stage on each audit.

### High

**H1. A valid CONFLICT is downgraded whenever aggregation abstains. CERTAIN.**

- **The mechanism.**
  - Any blocking issue makes the final verdict the LLM's holistic label
    (`verdict_aggregator.py:1227-1242`).
  - That includes a predicate defect on a *non-failing* sibling, or the
    extraction-incompleteness flag.
- **The impact.** This, together with H2, explains most stable misses.
- **Fix:** when a VALID FAILED sits on a conjunctive path, emit CONFLICT with mandatory
  review, and never downgrade it.

**H2. Scope and parameter checks run on the whole chunk, not the cited span. CERTAIN.**

- **The mechanism.**
  - `_isolate_relevant_passage` returns its input unchanged (`claim.py:293-305`), so one
    multi-requirement table row decides the scope for all of them.
  - Parameter alignment is described as advisory (`evidence_qualification.py:209-212`) but
    enforced as a hard gate (`verdict_aggregator.py:321`).
- **Fix:**
  - Infer scope from the cited span.
  - Treat a row that names the requirement's own code as in scope.

**H3. Retrieval drops valid evidence whose ID is formatted differently. CERTAIN** (code).

- **Formatting drops chunks.** `retrieval.py:165-171` skips any chunk whose codes don't
  exactly equal the lowercased target. These never become candidates:
  - "REQ_NVA_ELE_003" (underscores);
  - "REQ-NVA-ELE-001 to REQ-NVA-ELE-005" (a range).
- **A loose boost misfires.** The `TC-…-NNN` boost matches on the numeric suffix alone, so an
  unrelated TC-THM-003 gets +6 for ELE-003.
- **Fix:**
  - Normalise separators, case and leading zeros.
  - Expand ranges.
  - Demote unmatched chunks instead of dropping them.
  - Require the domain token for the TC boost.

**H4. The requirement-start regex creates phantom requirements. CERTAIN** (tested).

- **The pattern.** `_REQUIREMENT_START_RE` (`extraction.py:564`) accepts `R[-_]?…\d+`.
- **False starts.** Lines beginning "RS-485 …" or "R134a …" start new requirement blocks.
- **Lost suffixes.** "REQ-001-A" and "REQ-001-B" collapse to the same code.
- **Fix:**
  - Drop the bare `R…` alternative.
  - Allow letter suffixes: `(?:-[A-Z])?\b`.

**H5. Auto-closure is too rare, for reasons unrelated to evidence quality. CERTAIN.**

- **The numbers.** 2–3 of 48 auto-close against about 20 expected.
- **The causes.**
  - 24 of 48 contracts are flagged incomplete (every -004 to -006, `extraction.py:2831-2849`;
    LIKELY an incomplete source map).
  - The CONFLICT gate requires agreement from the holistic label, which the spec says not to
    trust.
  - The SUPPORTED gate uses raw LLM confidence (85–100) against a threshold of 90.
- **Fix:** fix C1 and C2 first, then replace these gates with signals Python computes.

**H6. Visitor and lead personal data is exposed. CERTAIN** (frontend review).

- **No access control.** Anyone who can open the app can list, CSV-export and delete every
  lead (`settings.tsx:23-41`). The table also caps silently at 50 rows.
- **Silent collection.** The backend stores IP and User-Agent without disclosure
  (`visitors.py`).
- **A misleading notice.** The capture modal is dead code, but its notice understates what
  is collected.
- **Fix:** remove the leads table or put it behind an admin role, and either delete the
  modal or add opt-in and disclosure.

### Medium

**Verdict engine**

- The range-envelope rule is applied to *measured* results.
  - Measured [4.5, 5.5] V against a requirement of [4.9, 5.1] V passes.
  - Insulation measured at [50, 500] MΩ against ≥100 MΩ passes (`verdict_aggregator.py:1494-1505`).
- `==` has an implicit ±2.5% tolerance, so 12.29 V passes "== 12 V".
- A temperature *rise* is converted as an absolute temperature, so a 40 °F rise becomes 4.4 °C.

**Ingestion**

- **Wrong section labels.** Section paths come from the page's *last* heading, so tables are
  mislabelled.
- **Running headers become chunks.** In the four Nova reports, at least 9 of 68 chunks are
  standalone running headers (short chunks containing "Page N of M").
- **Two-column text** is interleaved.
- **Scanned pages vanish silently** when Tesseract is missing.

**Performance**

- **Metadata bloat.** Full diagnostics are copied into every chunk (4× the text; grows with
  pages). Store them once per document.
- **Retrieval is pure-Python on the event loop**, and its "BM25" has no IDF term. Use an
  inverted index with numpy, run it in a thread, and precompute in `prepare_lexical_corpus`.

**Resilience**

- **Concurrency caps aren't real.**
  - Semaphores are created per call, so limits multiply by the requirement concurrency.
  - Vision and direct Databricks calls bypass the outbound LLM slot.
- **No overall timeouts.**
  - A TokenRouter stream has only a 60 s per-read timeout.
  - A vision cascade can make 14 attempts of about 90 s each.
- **Prompt injection.**
  - Document text is embedded in prompts without fencing.
  - The classifier keys results by the document name the model returns, so a PDF can relabel itself.
  - Vision output is merged into chunk text and then passes the literal-quote check.
- **Model substitution isn't recorded.** `construction_diagnostics` is never persisted, and
  there is a silent fallback to gpt-4o-mini when an OpenAI key exists.
- **The embedding circuit breaker opens permanently** after two 429s, for the life of the
  process. Diagnostics still say "local-hybrid".

**Frontend**

- **Error handling.** Requests have no timeout or abort signal, raw error JSON is toasted to
  users, and non-JSON proxy pages (SSO expiry, 413) throw.
- **Uploads.** No progress, no client-side size check, and a 413 arrives only after the full upload.
- **Shared links.** The active project lives in localStorage, not the URL, so shared
  requirement links open the wrong project.
- **Sub-path deployment.** Root-absolute favicon, logo, image and "Go home" links break under a sub-path.
- **Accessibility.**
  - Clickable `<tr>` and `<div>` elements aren't keyboard-focusable.
  - Selected state is shown by colour only.
  - Search fields are labelled only by placeholders.

**Platform**

- `app.yaml` installs Bun and rebuilds the frontend on *every* app start. Ship a prebuilt `dist/` instead.
- The workspace URL and warehouse ID are hardcoded in `app.yaml`.
- `DEPLOYMENT.md` and `deploy.sh` are empty (0 bytes).
- The upload directory is relative to the working directory. The README runs from `backend/`
  and `app.yaml` from the root, so the two use different folders.
- `audit_progress` uses synchronous SQLite on the event loop, and `claim_next` scans the whole table.
- `resolve_secret` makes a blocking SDK call on every access and does not cache failures.
- `trigger_audit` does not validate the model name.
- The README's run-report links point to `evaluation/results/`, which is git-ignored.

**VERIFY on a real workspace**

- The Databricks native parameter limit (batch inserts are capped at 250 parameters).
- The pipeline's stale-chunk `IN (…)` list on very large documents.
- The Databricks Apps proxy upload limit.

### Low

- **Dead dependencies:**
  - 20 Radix packages;
  - embla-carousel, react-day-picker, date-fns, input-otp, vaul, react-resizable-panels,
    react-hook-form and @hookform/resolvers;
  - 34 of 46 `ui/*` files.
  - recharts adds 97 KB gzip for one donut chart.
- **`frameworks.tsx`.** This orphan route shows hard-coded "Active" FMVSS 305, ISO 26262 and
  R100 badges. That is misleading in a compliance tool; remove it.
- **Colours.** Missing and Conflict are swapped between the dashboard and reports.
- **Downloads.** `revokeObjectURL` runs right after `click()`, which can cancel downloads in
  some browsers.
- **URL safety.** Path parameters aren't encoded.
- **Storage.** Access to localStorage is unguarded, so the app crashes when storage is blocked.
- **Unbounded growth.**
  - The embedding cache grows without limit.
  - `_chunk_locks` in `visual_analysis.py` grows without limit.
  - `pipeline_cache` sorts the whole table on every insert.

## Roadmap: making it the best audit platform

### Phase 1: Trust (first, about 1–2 weeks)

- **Close C1, C2 and C3.**
  - Check observed values against the cited span, and require full metadata for PROVEN.
  - Bind citations only to cited items, with a minimum quote length.
  - Add an egress allow-list that defaults to Databricks-only.
- **Record provenance.** Store the provider and served model per stage on each audit, and
  fence all document text in prompts.
- **Exit criteria:**
  - zero unsafe auto-closes on an adversarial probe suite (add the probes from this review as tests);
  - an egress report attached to every audit.

### Phase 2: Accuracy (about 2–3 weeks)

- **Build an offline replay harness first.** `results.json` already stores
  `verification_inputs` and `raw_llm_condition_results`. Re-running aggregation over them
  scores every verdict-engine change for free; today only paid end-to-end runs can.
- **Then fix the stable misses:**
  - H1: never downgrade a valid CONFLICT;
  - H2: scope from the cited span;
  - M: nested IF_THEN;
  - H5: the extraction-incompleteness flag (24 of 48 contracts);
  - H3 and H4: retrieval code normalisation and the ID regex.
- **Measure properly.** Run at least 3 paid runs per configuration and report the mean ±
  standard deviation. Track CONFLICT recall and the safe auto-close rate, not only accuracy.

### Phase 3: Scale and cost

- **Retrieval.** Use an inverted index with numpy, off the event loop.
- **Storage.** Store diagnostics once per document.
- **API.** Slim or paginate the requirements list (9 KB per requirement today).
- **Deployment.** Ship a prebuilt frontend instead of rebuilding at app start.
- **Databricks checks.** Verify the batch-insert and parameter limits against a staging warehouse.
- **Job registry.** Index the job table.

### Phase 4: Product

- **Navigation.** Put the project in the URL so links can be shared.
- **Access control.** Add roles (admin for leads and settings).
- **Operations.** Write real deployment docs and add a request timeout and abort.
- **Usability.** Do an accessibility pass on the review flow, and show upload progress.
- **Cleanup.** Remove the dead dependencies and the misleading frameworks page.
