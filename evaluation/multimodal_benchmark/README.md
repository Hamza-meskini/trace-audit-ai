# TraceAudit Multimodal Diagnostic Benchmark

This is a small, synthetic benchmark for diagnosing document understanding before investing in a 40-60 requirement corpus. It is not product training data and it does not encode any real company, vehicle or certification claim.

## Corpus

- `01_Aquila_BMS_System_Requirements.pdf`: controlled specification with 12 requirements and explicit `ALL_OF`, `ANY_OF`, and `IF_THEN` logic.
- `02_Aquila_Design_Validation_Test_Report.pdf`: executed laboratory evidence with ten reconstructed tables and three technical plots.
- `03_Aquila_Qualification_Inspection_Dossier.pdf`: post-test inspection evidence with a realistic equipment photograph, a technical diagram, contradictory findings, and certificate review.

The ground truth contains 25 atomic conditions and every condition has evaluator-only document, page, block type, evidence role, and quote provenance. Final labels cover all product states: 5 supported, 2 partial, 3 conflict, 1 missing, and 1 unknown/inconclusive.

Intentional hard cases include:

- one cross-page calculation whose operands are on page 4 and formula/result are on page 5;
- conflicts between an in-run observation and a later direct inspection;
- a visual marking photograph that is relevant but cannot establish identity or population scope;
- a technical plot that proves shutdown but contains no recovery cycle;
- an `ANY_OF` requirement with one proven and one untested branch;
- a genuinely unexecuted `IF_THEN` drive-away test.

## Generate and validate

```powershell
.\backend\venv\Scripts\python.exe evaluation\multimodal_benchmark\generate_multimodal_benchmark.py
.\backend\venv\Scripts\python.exe evaluation\run_multimodal_benchmark.py --validate-only
```

The generator expects `assets/service_disconnect_inspection.png`, the synthetic visual-inspection photograph generated for this pack. Deterministic plots and diagrams are regenerated by the script.

## Stage-isolation runs

Start with oracle passages to measure profiling, vision, condition reasoning, logic and aggregation:

```powershell
.\backend\venv\Scripts\python.exe evaluation\run_multimodal_benchmark.py --mode oracle-contracts-evidence
```

Then add real retrieval:

```powershell
.\backend\venv\Scripts\python.exe evaluation\run_multimodal_benchmark.py --mode oracle-contracts
```

Finally evaluate the complete path, including requirement and atomic-condition extraction:

```powershell
.\backend\venv\Scripts\python.exe evaluation\run_multimodal_benchmark.py --mode end-to-end
```

The default primary reasoning model is `system.ai.llama-4-maverick`. Pass `--model` to compare another endpoint. Result filenames contain the model identifier so one model run cannot overwrite another. The runner writes JSON and Markdown reports under `evaluation/results/`.

## Model-endpoint policy

Do not use a single hosted endpoint as an unmeasured dependency. Pin exact model identifiers, record provider/model/latency/error data in every result, use bounded retries for transient errors, and keep vision and text reasoning replaceable behind adapters. A fallback endpoint improves availability, but changing providers is not a substitute for stage-level evaluation. Run each release candidate three times only after the corpus and labels are frozen; report mean accuracy, worst-run unsafe false auto-closes, and prediction disagreement.
